# 算法事实与实测记录

本机实测：Linux / CPU / OpenCV 4.11 / onnxruntime 1.29 / numpy 2.5.4。换机器数字会变，结论不变。

## 线稿（生成式）

- 线稿由 `image_gen` 出图，**不是算法提取**。特征：等宽（中位线宽 5px / 1344×1792）、纯黑白、闭合、可有虚线缝线与彩色点缀。
- 生成结果的形状是"重新画的"：包口结构会被合理化、印花会被画成标准图形。
- 同一张图两次生成结果不同，**必须生成一次后固化复用**，产线里不要反复生成。

## 连通域分区（核心）

输入 white-on-black 二值线稿，`free = ~ink` 做 8 邻域连通域，排除与画面边界相连的背景块，剩下的封闭白区即候选分区。

分类规则（`regions_extract.py`）：

| 条件 | 归类 |
| --- | --- |
| 面积 < `min-area-pct`（默认 0.4%，按包面积算） | 太小，丢 |
| 其余 | 结构分区（全部保留） |

**不做语义/几何启发式过滤**——不猜细长条=缝线、不猜小实心块=印花。误杀结构件的代价 > 漏放印花的代价：漏放了用户在页面上一秒就能删，误杀了要重生成线稿。

实测一张 1344×1792 的包袋线稿（墨迹 4.01%）：连通域 168 个，结构分区自动给出 **5 块**（包身 22.0%／背带 3.7%／翻盖右 2.0%／翻盖左 1.7%／顶条 0.5%），印花与碎块 161 个。

### 边界性质

- 分区边界**完全由线决定**。包身与侧片如果中间没有线，就是一个连通域，切不开。想要多一块，必须在线稿里补线，不要再加形态学或聚类去硬猜。
- 同色/同料的子部位（翻盖与包身）靠"线"分开，这是它比 GrabCut 干净的原因；GrabCut 靠颜色建模，同布切不开。

## 矢量化的两个坑

1. **孔洞必须保留**：分区掩膜里有大量内部孔洞（印花被挖空）。用 `RETR_CCOMP` + `fill-rule:evenodd` 一次成型；不要只用外轮廓，否则填色会盖住印花。
2. **不要给分区描边**：相邻分区共享边界，逐区描边会画两遍变粗；带孔洞的分区描边会把每个孔都勾出来，视觉上是满屏虚线。正确做法是**只叠原始墨迹层**（`ink_layer.png`，alpha = 墨迹浓度），分区路径只用于裁剪填色。

## 渲染事实（build_page.py）

- Canvas 2D 渲染，画布尺寸 = 线稿原始像素，CSS 缩放显示。命中测试用 `Path2D + isPointInPath`，坐标直接是图像坐标，不需要变换换算。
- 面料平铺：`createPattern(img,'repeat')` 直接铺会出接缝。**必须四边镜像拼接**（2×2 镜像 tile），否则一块布铺满画面会出现十字接缝。
- 默认缩放取 `W*0.46 / tile.width`，让布样约铺半幅画面，接近真实印花尺度。
- 光照：每个分区按 bbox 拉一条沿光向的线性渐变，暗侧 `rgba(0,0,0,0.46*I)`（source-over），亮侧 `rgba(255,255,255,0.30*I)`（screen）。分区各自受光，互不影响，视觉上接近成品照。
- 填充优先级：**本区纯色 > 本区面料 > 色板兜底**，逐区填，不铺整包底布。

## 已知限制

- 明暗是合成的，不是真实褶皱。深色面料 + 白线稿的组合建议把线稿调成白色（页面有开关）。
- SVG 导出不含光照（矢量无法逐区实时打光），这是刻意取舍。
- 单页体积：含 `ink_layer` 的 RGBA PNG 后约 300–900KB，仍在 2MB 以内。若要做多款式模板库，按款式拆文件。

## 页面导出：只有成品 PNG

页面里的分区 SVG 导出、编号图导出、面料清单导出已在 2026-11 全部删除（连同 `--export all` 开关）。原因：编号图与分区 SVG 由 `regions_extract.py` 在 Step 3 已经产出、内容重复；而页面版 SVG 的线稿是位图墨迹叠层、面料是位图 `<pattern>`，8 区各一套参数最坏 ~2.7MB，拿去打样并不实用。现在页面只提供「导出 → 成品 PNG」。

## 去背（GrabCut）：为什么默认不做

本机实测，结论是**不要用算法去背去预处理喂给生成模型的照片**。

| 输入 | 背景与主体色差 | 结果 |
| --- | --- | --- |
| 浅底合成包（1200×900，浅灰背景） | ~248/255 | 前景 36.8%，掩膜干净，凸包外 0%，无告警 |
| 深色桌面 + 藏青条纹包（1920×1277） | 5–8/255 | 前景 45.3%，但右侧投影被算成主体（凸包外 57%），同色像素占 27% |

- 条纹包背景 BGR `[28,31,34]`，藏青条纹 `[36,39,42]`、藏青底块 `[28,29,32]`，皮标 `[148,184,213]`（距背景 201），米白布 `[204,222,238]`（距 248.9）。
- 即：**任何基于颜色的分割都会把藏青条纹与背景一起处理**，调参只是在"吃掉条纹"和"留下投影"之间来回。
- 有效区间和需求区间相反：色差大的图本来不需要去背，需要去背的图恰恰切不准。这类算法只适合处理简单情况。
- 正解：在生成提示词里写"纯白背景、浅灰地面、不要桌面与投影阴影"，让生成模型换背景。换背景零成本。
- 生成过线稿的照片**再喂一次**去背图是负收益：边界咬进包体（提手内侧/包底暗部）后，生成模型会照着缺角的图作画，错误放大成线稿结构缺失。
- 浏览器端不可行：`opencv.js` 的 `cv.grabCut` 接口坏（`7083008`/`7083328`）；SAM 权重 13.8MB + wasm 10MB 级，塞不进单文件页面。
