# 线稿提示词库（直接喂原图，不再人肉选骨架）

生成线稿的稳定性不靠"先判断包型再选骨架"——模型多模态能力比人肉分类准，
直接把原图作为参考图喂给 `image_gen`，提示词只保留两段：
**通用块**（反踩坑约束）+ **结构线要求**（告诉模型要画哪些闭合分割线）。

用法：
1. 把原图作为参考图传给 `image_gen`（`image_reference_url_list`）
2. 提示词 = 下面的**通用块** + **结构线要求**，整段照抄，不要改写、不要自己加品类名
3. 出稿后跑 `preflight.py` 体检；漏画结构时，翻到底部「常见包型结构线参考」挑一句补进去重生成

**为什么不让 agent 先认包型**：模型自己看图就能认出这是托特/水桶/翻盖，
比 agent 读照片再念品类名准且快。agent 中间那层"读 prompt.md、挑骨架、抄结构清单"
是多余的翻译环节——真正不能省的是下面两段踩坑约束，模型自己不会知道。


## 通用块（每次必抄，实测有效）

```
整张图只有纯白底和纯黑线，绝对不许出现彩色、灰阶、阴影或网点；
线条细而均匀等宽、干净闭合、无断线；
所有部位内部一律留白、绝不填黑；
不要画任何文字、字母、品牌标识或 logo；
不要画任何纹理、花纹、鳞纹、铆钉、缝线装饰线——只画结构分割线；
不要背景物件、桌面、墙面和投影，只画这只包本身，居中，四周留白。
```

这四条是踩出来的：
- 不写"内部一律留白、绝不填黑" → 深色部位被填成实心黑块，连通域切不开（条纹包实测）
- 不写"绝对不许出现彩色" → 直接返回红底彩花插画（花布包实测）
- 不写"不要文字/logo" → 品牌字糊成错字，而且会被当印花块污染分区
- 不写"不要纹理/花纹/鳞纹" → 鳄鱼纹、铆钉、缝线装饰线被画进线稿，碎成几百个小分区（t30 鳄鱼纹包实测）


## 结构线要求（每次必抄，通用，不绑定包型）

```
根据这张照片里的包袋，画出它的分区线稿：
不要脑补、不要添加，严格复制照片里的包；
不要画照片里没有的任何东西；
严格参照参考图的视角、透视角度和比例关系，不要重新摆成正视图，保持照片里的视角；
不要改变任何部件的大小，提手多长、翻盖多大、包身多宽，都和照片里一模一样；
部件位置和照片里一致，不要移动或翻转；
包身外轮廓形状和照片里一致，不要改变圆角、方角或曲线；
只画照片里实际可见的结构分割线，包括但不限于：
袋口翻边/口金框/拉链口、袋底折边/袋底底片、左右侧缝/侧幅、
提手/肩带/链条（画成空心闭合带，带子内部一根线不要）、
翻盖/锁扣/磁扣、前袋/后袋/侧袋/贴袋、镂空孔/手提孔；
多条提手或肩带各自独立闭合，不要连成一条。
```

为什么要写这段：
- 模型不知道你要的是"可分区线稿"，它只会画一张好看的外观线稿，
  不会主动画出能切分的闭合结构线。不写这段，切出来常常只有外轮廓 1–2 块。
- 角度还原是默认行为：模型会把包重新摆成标准正视图，必须显式要求它保持照片视角。

**不要在提示词里写品类名**（"帆布托特包""水桶包"之类）——模型自己看图就知道，
写了反而限制它按照片实际结构画。

**角度还原的已知风险**（斜三分之二视角实测）：
- 斜挎带/肩带如果正好压在袋口翻边上，会把翻边劈成前后两段，换色要选两次
- 透视下会多出碎块（折边碎片、看不到的侧面窄条），`--keep` 时要手动剔掉
- 短提手可能画不完整，连通域切不出来
- 整体分区数量比正视图版少 1–2 块

这些风险是"角度还原"的代价，用户要的就是和照片长得像，分区碎一点可接受。
不要为了分区干净而默认转正视图——用户明确传照片就是要这个角度。


## 附录：常见包型结构线参考（漏画时补，不是事前必选）

如果 `preflight` 说结构线不够、或编号图发现漏了部位，对照这里挑一句补进提示词重生成。
**不需要事前选骨架**——模型自己看图决定画哪些线。这里只是"模型漏画时的补药"。

### 开口托特 / 帆布收纳篮

> 预期 5–7 块

补这句：
```
袋口上沿画一条横向翻折边——翻边上下各一条缝线、左右两端与袋身边线相接完全闭合，形成独立窄横条；
包身最下方一条横向缝线，把底部切出独立的窄横条（袋底折边）；
两条手提带各自是独立空心带，带子内部一根线不要，两条提手顶部不要连成一条。
```

命名参考：`包身主面 / 袋口翻边 / 袋底折边 / 提手 / 左侧幅 / 右侧幅`


### 翻盖斜挎 / 小方包（链条包同族）

> 预期 5–7 块

补这句：
```
包身正面一块从上沿盖下的翻盖，翻盖左右两侧各有一条侧边条（与翻盖、包身都闭合）；
翻盖下沿中间有一个锁扣（方形块）；包身两侧各一条竖缝切出侧幅；
一条链条肩带从包身两侧伸出，画成一段段椭圆的链条（每段闭合）。
```

坑：链条画成连续波浪线会碎成几十个小块 → 明确"一段段椭圆、每段闭合"；锁扣太小会被 `min-area-pct` 过滤，必要时手动补。


### 水桶包（含抽绳）

> 预期 4–6 块

补这句：
```
收口处画一圈抽绳（绳子用一条细波浪线，两端各一个绳结）；
抽绳下方画 3–5 条从收口向下发散的褶线，把袋身上部切成几块；
袋底是一个椭圆形底片（闭合）。
```

坑：褶线画成装饰虚线（不闭合）→ 上部切不开，只能算一整块。


### 马鞍包

> 预期 4–5 块

补这句：
```
一块弧形翻盖从上沿盖下，翻盖边缘有一条描边缝线；
翻盖下方露出袋身一块弧形区域；一条短肩带从包身两侧向上、顶部有金属调节扣。
```


### 腋下包 / 法棍包

> 预期 3–5 块

补这句：
```
上沿一条拉链（拉链头在中间）；包身左右两端各一条竖向侧缝；
一条短肩带从两侧向上，肩带贴合包身走向。
```

坑：横向扁包在竖构图里容易被画小 → 补一句"画面横向撑满，上下留白"。


### 双肩包

> 预期 6–8 块

补这句：
```
正面一块前袋（闭合的方形，带一条拉链）；左右各一个侧袋（闭合）；
顶部一条提手；两条肩带从背部垂下，各自闭合，带子上有调节扣。
```

坑：肩带画成交叉或穿过包身 → 切出一个大 X 形废块；补一句"两条肩带各自独立、不交叉"。


### 硬壳手提 / 箱型包

> 预期 4–6 块

补这句：
```
上下两半箱体中间一条横向分割线（闭合）；箱体正面一个方形锁扣；
左右两侧各一条竖向硬边线；顶部一条弧形提手（空心带、独立闭合）。
```


### 云朵包 / 枕头包 / hobo 软塌包

> 预期 2–4 块，不要期待 6 块

补这句：
```
袋身中间画 1–2 条从上到下的柔和褶线（把袋面分成左右两块）；袋口一条短拉链。
```

坑：软包没有结构可切，硬要 6 块只能靠印花切碎，切出来全是 0.4% 的小块，不能用。


### 编织 / 草编 / 藤编

> 预期 1–3 块，纹理必然污染连通域

补这句：
```
编织纹理只用稀疏的斜向短线暗示，不要画满整张袋面的网格。
```

坑：画满网格 → 每根编织线都闭合出一个小块，几百个 0.1% 的碎区被 min-area-pct 过滤，最后只剩外轮廓一块。


### 圆筒 / 波士顿包

> 预期 4–5 块

补这句：
```
左右两端各一个圆形端片（闭合），筒身中间一条缝线；袋口一条横向拉链。
```


## 材质档（同包型下，材质决定上限）

| 材质 | 结构线好不好画 | 现实上限 | 备注 |
| --- | --- | --- | --- |
| 硬壳 / 硬皮（箱型、链条小包） | 好，边缘天然闭合 | 5–8 块 | 最省事 |
| 帆布 / 尼龙（托特、双肩） | 中，靠缝线补 | 4–7 块 | 提示词必须点名"缝线" |
| 软布 / 碎花 / 绒面（花布包、云朵包） | 差，没有内缝线 | 2–4 块 | 靠褶线；花色会被切碎 |
| 编织 / 草编 | 很差 | 1–3 块 | 纹理毁掉连通域 |


## 出图后 5 秒体检（不要先建页）

```bash
python3 scripts/preflight.py --image work/lineart_gen.png --keep-file work/lineart.png
```

它给一行结论 + JSON：
- `verdict: pass` → 往下走（预处理稿已落 `lineart.png`）
- `verdict: regenerate` → 看 `hints` 决定加哪句，重生成一次
- `verdict: blocked` → 线稿完全不可用，禁止降级交付，必须重生成

判定口径与 `regions_extract.py` 同一套（只按最小面积过滤，其余全保留），所以体检说"能切 N 块"，实际就切 N 块左右。


## 止损（别再"再试一次看看"）

1. **同一只包最多生成 2 次**。第 1 次体检不过 → 按 `hints` 补一句重生成；第 2 次仍不过就**停下来**。
2. **`blocked` 状态必须停止，不允许降级交付**：墨迹严重超标、背景严重不足、分区少于 2 块时，说明线稿完全不可用，必须重生成。
3. 第 2 次仍 `regenerate` → **降级交付**：用能切出的那几块建页（哪怕只有 2 块），在回复里写清"这只包的结构线只够切 N 块，想更多块得我再手动补线稿或换更硬挺的包型"。
4. 不要出现"第 1 版 / 第 2 版 / 第 3 版"连着试——三次里后两次的增益通常接近 0，真正让第二版过关的是**提示词里补了结构清单**，不是"又试了一次"。
