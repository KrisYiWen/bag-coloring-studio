# 包包敷色｜包袋线稿分区敷色工作台

用户传一张包，产出的核心是**可点选换面料的包包敷色工作台**。编号图与分区 SVG 是中间产物（内部核对用），**不随交付发出去**。

## 0. 流程红线（本节优先于后文任何冲突描述，不许退化）

1. **先问用户，再决定怎么走**。用户传照片后，先问一句"要我自动做完直接提供包包敷色工作台，还是先出线稿给你看，满意了再继续？"用户选自动跑完就一路跑完直接交付；用户选先看线稿就分轮次，先用 present_files 交付线稿图片等确认。
2. **分区全保留，不做语义判断**。不判断「这块是背景洞 / 印花 / 缝线」，不删任何闭合区域。编号跑完直接建页，让用户在页面里决定哪块上色。
3. **唯一必交物是包包敷色工作台**。成品 PNG、编号图、分区 SVG、面料清单一律不主动交付、不主动代跑；用户明确要才做。
4. **交付回复只写一句结论**。不列分区表、不报分区编号清单、不复述页面有哪几个 tab、不写能力边界。页面本身已经把信息摆全了，用户打开自己看。

## 0.1 不接的范围

- 衣服 / 鞋 / 帽子：不接。说明本技能只覆盖包袋的分区逻辑，硬套会把袖子和衣身糊成一块。

## 1. 五条铁律

1. **线稿一律是生成出来的**，不许用算法提取冒充好看稿；产物文件名必须带档位：`lineart_gen.png`，不许同名覆盖。
2. **生成一次，固化复用**。后续换面料、改色、调光、导出，全部读固化资产；重新生成只允许两种情况：`preflight.py` 体检不过（同一只包最多补一次），或用户明确说"重画"。
3. **交货前必须过 `qc_check.py`**。不通过就按失败处理走，不许硬交。
4. **页面必须单文件、离线可开**，体积目标 < 2MB。
5. **分区边界完全由线决定**。想要多一块分区，就在线稿里多画一条分割线；不要指望算法猜出同色同料的子部位。

## 2. 工作流

```bash
S=scripts
W=work

# Step 1 出线稿
#   把原图作为参考图喂给 image_gen，提示词 = references/prompt.md 的通用块+结构线要求
#   产物落到 $W/lineart_gen.png
python3 $S/preflight.py --image $W/lineart_gen.png --keep-file $W/lineart.png

# Step 3 分区：一次跑完，全部保留
python3 $S/regions_extract.py --lineart $W/lineart.png --out $W/regions --max-regions 30

# Step 4 质检
python3 $S/qc_check.py --regions $W/regions/regions.json

# Step 5 出工作台
python3 $S/build_page.py --regions $W/regions/regions.json --out $W/包包敷色工作台.html \
  --title "包袋分区敷色" --note "先点分区，再点颜色或面料"
```

## 2.5 先问用户：自动跑完还是先看线稿

用户传照片后，**先问一句**，用选项按钮的方式，让用户点选不用打字：
> "要我自动做完直接提供包包敷色工作台，还是先出线稿给你看，满意了再继续？"
>
> 选项：**「直接做完」** / **「先看线稿」**

- **用户选"直接做完"**：一路做完，直接提供包包敷色工作台。
- **用户选"先看线稿"**：必须先完成以下步骤，才能问用户满意不满意：
  1. 生成并预处理线稿，确认 lineart.png 存在且有效
  2. 调用 present_files 把线稿图片交付给用户
  3. **确认图片交付成功后**，再单独问一句："线稿出来了，满意的话我继续往下做？"
  - 选项：**「继续往下做」** / **「不满意，重画」**
  - 选继续 → 往下做完，提供工作台
  - 选重画 → 按 hints 补一句重生成线稿
  - **禁止**：图片还没交付就直接问用户满意不满意

## 2.6 止损：不许连着试三版

1. 同一只包最多生成 2 次。第 1 次体检 `regenerate` → 按 `hints` 补一句再出一次；第 2 次仍不过就停。
2. **`blocked` 状态必须停止，不允许降级交付**：墨迹严重超标、背景严重不足、分区少于 2 块时，说明线稿完全不可用，必须重生成。
3. 第 2 次仍 `regenerate` → 降级交付：用能切出的块数做出工作台（哪怕只有 2 块）。
4. 不许"再试一次看看"。真正让第 2 版过关的是提示词里补了结构清单，不是"又试了一次"。

## 2.7 禁止无头浏览器验证

**交付流程中绝对禁止**调用 Playwright、浏览器自动化、截图验证或任何无头浏览器工具。
- `qc_check.py` 通过后立即 `build_page.py` 并交付，不要等截图验证
- 不要因为"想看看页面长什么样"就启动浏览器
- 开发者自测工具不在用户交付流程中使用

## 3. 分区参数

默认 `--min-area-pct 0.004`（按**包面积**比例算），只做一条过滤：**太小的噪声碎点丢掉，其余全部保留**。

**不做语义/几何启发式过滤**——误杀结构件的代价 > 漏放印花的代价。

## 4. 交付规范

必交：`包包敷色工作台.html`（单文件，双击可开）

**回复模板**：
> 做好了，打开点区域再选颜色或面料。

降级交付时：
> 这只包只能切 3 块，先这样用；想要更多区域得换一只结构更硬挺的包。

**成品图默认不交付**——页面里自带导出，用户自己点就行。
